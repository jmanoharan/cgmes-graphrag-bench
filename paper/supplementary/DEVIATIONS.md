# Deviations Register: v2 Experimental Run (2026-06-11)

PROPOSAL.md §3.1 requires: *"Any deviation from these frozen parameters between conditions is a
protocol violation and must be reported."* The v1 run (2026-06-10) violated several frozen
parameters without reporting them; this register documents (a) every v1 violation, (b) the v2
fix, and (c) every remaining v2 deviation from the pre-registration, with rationale.

## A. v1 protocol violations: fixed in v2

| # | Frozen protocol item | v1 violation | v2 status |
|---|---------------------|--------------|-----------|
| A1 | Ground truth = "public CGMES / IEC 61970 export" (§3.1) | Used pandapower `case14.json` (a simulation-package format) with **author-invented relation labels** (`CONNECTED_VIA_LINE` etc.) that are not CIM terms; data contained MATPOWER placeholder artifacts (0.208 kV transmission buses, 9 900 MVA transformers, all lines 1.0 km) and internal contradictions (Bus 4 listed at both 0.208 kV and 135 kV) | **Fixed.** G_STD is parsed directly from the ENTSO-E CGMES v2.4.15 Conformity Assessment *MicroGrid Test Configuration* (BaseCase Assembled BE+NL+Boundary), with real mRIDs and real CIM association names (`Terminal.ConductingEquipment`, `Equipment.EquipmentContainer`, …). All values are the standard's own engineering data. |
| A2 | Reader = open-weight Qwen2.5-7B on local GPU (§3.1, compute envelope) | Reader was Azure gpt-5.1 (unregistered, much stronger, same model as builder & judge) | **Fixed.** Reader is Qwen2.5-7B-Instruct, local, greedy decoding, identical prompts for both arms. |
| A3 | Identical retrieval for both graphs; only the edge set differs (§3.1) | Custom regex pipeline injected a **full bus-voltage reference table into the G_STD context only** (an answer table for many S1 items); entity parsing was built around G_STD ID conventions; G_LLM seeds were resolved through G_STD's node map | **Fixed.** Single retrieval code path for both arms: seeds matched against each graph's own node names, 2-hop expansion, uniform triple rendering, identical 8 000-char cap, identical fallback rule. No per-graph tables. |
| A4 | H1 taxonomy: Type A = "directly violates the CGMES/IEC model"; Type B = corpus-consistent, **excluded from precision denominator** (§3.2) | All 44 aligned edges scored Type A purely because LightRAG's natural-language labels string-mismatched the invented enum labels; Type B was never effectively applied; headline "100% error rate" was a labeling artifact contradicting the frozen definitions | **Fixed.** v2 scorer separates **endpoint support** (does the CGMES model connect/contain/relate these two objects?) from **label fidelity** (does the natural-language label map, via a frozen synonym table, to a class compatible with the CIM relation?). Label mismatch alone is not an error. Type B (corpus-expressed, schema-absent) is excluded from the denominator as registered. Full per-edge audit trail in `data/v2/h1_edge_audit.json`. |
| A5 | ≥2-3 judges + human spot-check, judge agreement κ reported (§3.3) | Single judge (gpt-5.1 - same model that generated the corpus and read the answers) | **Resolved.** Primary H2 scoring is now **deterministic** (machine-checkable `answer_spec` per item); two LLM judges from different families (Azure gpt-5.1 + Claude Haiku) are secondary; all pairwise κ reported. Human spot-check on 10 items (20 paired verdicts) completed: 20/20 agreement with the deterministic scorer (κ=1.0); per-item annotations in `HUMAN_SPOTCHECK.md`. |
| A6 | Corpus = text describing the network (§3.1) | 1 748-word corpus generated by gpt-5.1 (same model as builder and judge → circularity); internally inconsistent | **Fixed.** Corpus is a **deterministic template rendering** of the CGMES model (no LLM anywhere in ground-truth or corpus generation); every relational sentence is logged to `corpus_facts.json` before G_LLM exists (frozen Type-B registry). |
| A7 | H3 = tokens + calls + wall-clock (§3.4) | Token counts not logged ("multiple batches"); narrative reported the wall ratio as ~1.87×10⁵ while the data file said 1.87×10⁶ | **Fixed.** Exact per-call usage accounting (prompt/completion/total tokens, call count); ratio recomputed from logged values. |

## B. Remaining v2 deviations from the pre-registration (disclosed)

| # | Registered item | v2 deviation | Rationale |
|---|----------------|--------------|-----------|
| B1 | Test case: "IEEE 14-/39-bus CGMES test case" | ENTSO-E CGMES Conformity MicroGrid (Assembled BE+NL) used instead | No authoritative public CGMES export of IEEE 14/39 exists; the ENTSO-E conformity models are the **reference CGMES artifacts** the industry validates against, strictly closer to the paper's claim ("a real deployed engineering standard"). Network is smaller than IEEE 14-bus in bus count but far richer in CIM structure (233 objects, 18 association types, 3-winding transformer, tap changers, boundary set). |
| B2 | Statistical test: Wilcoxon signed-rank (§4) | McNemar exact is primary; Wilcoxon (sign-test reduction) also reported | Outcomes are paired binary; McNemar is the appropriate exact test. Both reported; conclusions identical. |
| B3 | "3 judge models + human spot-check on 10 items" | 2 LLM judges (gpt-5.1, Claude Haiku) + deterministic primary; the registered OpenAI third judge was unavailable (API quota exhausted); human spot-check completed post-hoc | Deterministic primary scoring is stronger than any judge for this QA set (gold answers are machine-checkable numbers/entities). Human spot-check on the registered 10 items (20 paired verdicts across both arms) agreed with the deterministic scorer on 20/20 (κ=1.0), confirming the deterministic verdicts. **Resolved.** |
| B4 | LightRAG dual-level retrieval (keyword + community summaries) for both arms | Both arms use the same 2-hop subgraph retriever (≈ the registered "BM25+1-hop uniform retriever" sensitivity study A3, run as primary) | Loading G_STD through LightRAG's ingestion API would re-describe CIM edges in LightRAG's own format and re-introduce asymmetric prompt phrasing; the uniform retriever is the cleaner instrument for the graph-source effect. The LightRAG-native retrieval contrast is future work. |
| B5 | CIM profile subset | OperationalLimitSet/CurrentLimit, ReactiveCapabilityCurve, RegulatingControl, GL/DY/SV profiles excluded from G_STD | Out of scope for topology/protection QA; kept classes listed in `scripts/v2/build_g_std_cgmes.py` (`KEEP_CLASSES`). |
| B6 | Entity alignment: "double-annotate 20-entity sample, Fleiss κ" | Alignment is fully algorithmic (exact name → prefix/suffix-stripped → unique fuzzy ≤2 → ambiguous excluded), with candidate-set semantics for CGMES duplicate names; no human second annotator yet | CGMES names are exact identifiers, so algorithmic alignment is near-deterministic; the per-edge audit trail (`h1_edge_audit.json`) substitutes for, but does not replace, the registered IAA check. Pre-submission TODO. |
| B7 | Sample size: 50 items (25 S1 / 25 S2) | Unchanged, but note the registered MDE (≈23 pp full set, ≈32 pp per stratum) still applies; sub-MDE effects are reported as inconclusive | - |

## D. Post-hoc additions during paper writing (2026-06-11, after outline review)

| # | Addition | Status |
|---|----------|--------|
| D1 | **SmallGrid second case** (reviewer demand M-1). Same frozen pipeline, parameterized scripts. | Confirmatory for H1 (error 0.09%, recall 34.0%); for H2 it **reverses** the MicroGrid parity (G_LLM 98% vs G_STD 48% overall; S2 100% vs 12%, exceeds MDE).
